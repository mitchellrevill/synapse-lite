# Contributing

See [development](docs/development.md) for builds and tests, [architecture](docs/architecture.md) for ownership boundaries, and [compatibility](docs/compatibility.md) for support claims.

Use one coherent commit per change. Explain the resulting behavior and relevant validation. Keep regression tests, preserve upstream credit and avoid committing local captures, private profiles or generated vendor assets. Device support must be backed by protocol evidence and clearly separated from physical verification.

For UI changes, include a capture of the actual app state. Label simulated devices and unfinished behavior. Check that screenshots contain no serial numbers, account names or private paths.
