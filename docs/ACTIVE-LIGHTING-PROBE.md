# Active native Lighting probe

`secbird-tray.exe --runtime-lighting-probe 12` is an explicit development measurement mode (1..600 seconds), separate from `--runtime-smoke`. It starts the native tray, event listeners, normal uniform worker and native Lighting view. This command can emit RGB frames and reconcile its existing LIVE brightness policy. It does not prepare a profile, create opt-in, initialize device controls or apply an ordinary device profile.

Admission requires one exact serial-bound Ornata configuration with one active profile, retained positive brightness, an existing explicit native Spectrum/fixed Breathing opt-in, a matching source effect, clear ownership and supported pre-existing mode3/Custom8/LIVE/SAVED controls. Nonlighting settings (including a typed gaming-mode value of `off`), mappings, macros, linked applications, extra configured devices/profiles and unrecognized action metadata are rejected. Failure never falls back to ordinary startup. The Engine helper uses GET-only preflight and pins the admitted parsed configuration; changes or parse errors latch refusal before subsequent frames/brightness reconciliation. The probe performs fresh bounded configuration checks, so this measurement-only overhead is included in results.

For its entire lifetime, this mode skips generic profile apply, remap restoration, foreground-driven activation, legacy lighting reapply/laptop actions and input-event persistence. Native editor actions cannot submit writes. Worker shutdown and policy lease restoration retain their normal bounded behavior. These restrictions do not describe the ordinary product startup path.

Set `SYNAPSE_LITE_CONFIG_DIR` to the explicitly prepared existing lighting-only configuration and `SYNAPSE_LITE_ASSETS` to provisioned assets. The probe does not construct either. `SYNAPSE_LITE_SMOKE_VIEW` accepts `keyboard-lighting` (default), or `keyboard-lighting-color-editor` for an existing fixed Breathing profile. The color editor opens only a local draft; Spectrum is rejected for that presentation rather than substituted with another effect.

Set `SYNAPSE_LITE_SMOKE_REPORT` for the native frame JSON and `SYNAPSE_LITE_PROBE_REPORT` for the separate shutdown JSON. The frame continues updating during the probe. Its `matched` flag requires presented source assets/fonts plus a directly observed, owner-bound Lighting runtime no older than 2500ms, a live worker, streaming, at least three accepted frames, no cached errors and a recent control checkpoint (at least one check, age at most 500000 microseconds, fresh batch mode3). Nullable mode parameters remain unknown; checkpoint admission is not per-frame control verification or optical proof.

The final JSON separates pre-stop readiness/liveness from fresh post-stop cached error inspection. It reports accepted frames, observation age, worker stop, restoration failure count and clean-stop outcome without device keys or profile names. A missing/failed observation cannot become a successful result. `tools/Measure-ActiveLightingRuntime.ps1` consumes both reports; the flag itself makes no final RAM or pixel-fidelity claim.

The older `--runtime-smoke` continues to omit the uniform worker and keeps its existing startup behavior. Earlier read-only measurements used fresh configurations without actions; the flag alone does not yet intrinsically prevent generic profile application. Its memory results therefore exclude active uniform playback.

Validation for this unit uses simulated transport only: flag/conflict/admission/readiness tests, Engine GET-only admission/config-pin tests, and the four existing native HWND regressions. Physical active-runtime RAM measurement is a separate step.

The frozen simulated checkpoint passed 145 regular tray tests (6 opt-in tests ignored) and all 4 native HWND regressions in 4.04 seconds. See [active-lighting-probe-tests.json](validation/active-lighting-probe-tests.json). No physical active probe was executed for this validation.
