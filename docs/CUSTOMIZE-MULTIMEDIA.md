# Customize Multimedia assignments

This change adds the Multimedia category's source command dropdown and local desired-profile Save/Cancel to the existing native Customize popup. It does not alter the approved tabs. Volume Down/Up retain source `useTurbo: true`; other choices omit the flag. The ten stable source IDs are VolumeDown, VolumeUp, MuteVolume, MicVolumeUp, MicVolumeDown, MuteMic, MuteAll, Play, PrevTrack and NextTrack. Visible labels expand microphone names and Play / Pause.

Save uses the existing queued native action boundary at `/api/customize-multimedia`. It reloads the current store, checks connected device and active profile ownership plus the full original profile, creates a bounded complete candidate, then saves locally. Cancel only drops the owned draft. A failed save retains its draft. Unknown existing commands remain unselected until an explicit choice, with their source fields retained. Protected primary mouse click, unverified inputs, duplicate records, non-boolean layer identity and native mapping caches refuse editing. Standard/Hypershift records are independent. No native action is synthesized: the stale typed projection for exactly the edited input/layer is removed, while all other buttons, profile identity, source groups, metadata and other profiles remain intact. Existing source/native backup/export seams serialize the result.

**Output remains unavailable.** The status explicitly says the record was saved locally and device/host output is unavailable. Customize does not register a global chord or activate interception, injection, playback, hardware writes or driver work. A separately integrated Global Shortcuts execution seam remains distinct from device assignments.

Twenty controlled helper cases replay the recovered getMappingData body with an inert table converter, with no bundle bootstrap or vendor runtime. Rust command IDs match both independently extracted tables.
