# Source Wave controls and effect dropdown

The native Lighting view reaches source Wave effect **4** through the existing owner-bound `/api/source-effect` action. Its uncached source default is direction **2**; **1** means left and **2** right. These UI values are not firmware effect IDs. Backend prerequisites and supported output remain described in [HOST-WAVE.md](HOST-WAVE.md).

This checkpoint replaces the seven-row manual menu with the recovered generic source dropdown: 150px width, 180px border-box height, 178px content viewport, 25px rows, and an 8px scrollbar with a 6px colored thumb. It includes the partially visible eighth row, clipped hit regions, thumb dragging, track paging, upward opening when `trigger.bottom + 2 + 180 > innerHeight`, and scrolling the selected row into view on each open. Twelve rows produce a 300px scroll height and 122px maximum offset; Wave's 250px row offset therefore opens at 122px. Native wheel scrolling retains one row per notch; OS/Chromium wheel acceleration parity is unverified.

The shipped shared direction component invokes a toggle from **either** tab and the surrounding pill. Wave computes `direction == 1 ? 2 : 1`; clicking its active tab therefore switches to the other direction. Native controls now preserve this behavior and all other setting keys. Missing or unexpected direction values visually select the second tab, matching the source equality test; an unknown snapshot is not silently persisted as a default. Wheel and Tidal use the same shared component with their own recovered values.

Source evidence is pinned in [validation/wave-ui-native.json](validation/wave-ui-native.json): Ornata renderer classes `ZI`, `OI`, `Z_`, webpack module `27734`, exact UTF-8 ranges and SHA-256 hashes, CSS selectors, and REA summary `ev_7678ea5230f3a37291e75cc25f040b4d95d73d7936ab3dd814b1ab93a4a2ab52`. The four bounded projections parse without failures; semantic coverage remains partial with 949 unknowns. The geometry replay loads local shipped CSS in Chromium with network blocked and executes only our inert DOM-measurement code. It does not run vendor JavaScript or use screenshots.

Validation: 192 regular tray tests and eight opt-in simulated native HWND flows passed. The new HWND test exercises selected-row reopening, thumb capture/drag, narrow-view upward opening, the actual Wave row hit, and direction requests `2 → 1 → 2` with opaque data preserved. A **cfg(test)-only command sink** captures those requests before backend invocation; simulator commands and profile bytes remain unchanged. This is UI/request evidence, not physical Wave output, new RAM acceptance, or pixel identity. Source fonts and icons are reused; GDI glyph rasterization and fractional scrollbar rounding parity remain unproven.
