# Validation status

The source baseline is v0.5.0-beta1. At the Power implementation checkpoint, 180 workspace tests and two recovery-encoding example tests passed, with 5 opt-in tests ignored; the release build passed. Tests cover profile codecs and preservation, device framing/correlation, source Power routes/persistence/sleep provenance, and simulated device behavior including raw low-power threshold restoration. Five opt-in live/network tests remain ignored; passing the suite does not establish hardware parity.

Seven runtime runs included the normal tray, native editor, device worker/listeners and observed descendants at 125% DPI. Presented-frame evidence covers dashboard, the source Performance view, its scrolled polling panel and presentation-only independent/hidden row states, keyboard Lighting and keyboard Customize. The largest working-set high-water was 23,474,176 bytes; sampled private committed memory peaked at 8,515,584 bytes. No process-owned TCP connection was observed. Independent/hidden render overrides did not send device changes. These results cover recorded views and intervals; they do not prove complete functionality, visual identity, long-term behavior or removal of all installed Razer components. The seven-view evidence is in performance-views.json. Three further Performance checkpoint checks after stale-control guards are in runtime-memory.json, with explicit configured/visible/independent counts; their maximum working set was 24,207,360 bytes, still below 100 MB. Each file records its exact executable digest and scope.

The source-built fork successfully queried the isolated physical Ornata V2 firmware (1.1) and capabilities. Five physical setting write/readback checks now pass with exact raw restoration: mouse DPI, polling, sleep timeout and DPI stages; keyboard brightness. A controlled failure after a DPI write also restored every captured register. Lighting effects, mappings/macros, actual sleep/wake, reconnect and abrupt-exit recovery remain unverified. See installed-hardware.json and HARDWARE-CHECKS.md. All stock application changes during these recorded checks were temporary; Synapse was restored, and services/drivers were not removed.

A later wired mouse run passed eight checks, adding the low-power threshold and the typed disabled/hidden stage projections and activation behavior. The original threshold was captured as a raw byte and restored exactly with the other registers. See power-hardware.json and ../POWER.md. Three read-only native Power page runs then presented both hardware-backed controls, at a peak working set of 23,134,208 bytes and sampled private memory of 8,486,912 bytes. Their exact checkpoint is in power-native-memory.json. These checks do not establish battery-triggered mode transitions, wireless behavior or native pointer routing. Every memory report remains scoped to its recorded binary hash.

Synthetic CLI interoperability passed: Synapse 4 fixture import and re-export, native JSON export, and import/re-export through the original source-built Secretarybird beta with known settings retained. Older Secretarybird builds drop unknown extension metadata when saving, so their edits cannot be treated as lossless Synapse-source preservation. A real Synapse application import of the generated document remains unverified.
