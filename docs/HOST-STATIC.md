# Ornata host Static

Source Quick Effect Static uses one uniform 132-pixel frame when the Ornata V2 is already in Driver Mode3 with profile0/region0 CustomFrame8. It uses the [bounded source frame writer](ORNATA-FRAMES.md); it does not acquire a mode or write a saved effect. Normal Mode0 retains the firmware path.

The source endpoint checks the exact device, active profile, configured lighting ownership, known competing processes and aggregate profile budget before device access. It checks mode and CustomFrame state before and after the batch. Responses distinguish accepted USB writes and readable control state from visible output: `optically_verified` remains false. Partial transfers, failed postchecks and failed saves report possible hardware changes without automatic retry.

Profile activation, reconnect and the tray's policy reconciliation use the same bridge. A successful steady Static is not streamed. Failed attempts remain latched until explicit reapply, changed intent or reconnect. Disabled brightness and display/idle/away suppression retain a deferred color; resume prepares that color before raising live brightness. A failed pending frame blocks brightness resume.

In Driver3, explicit brightness changes retain configured intent and reconcile live brightness after frame preparation. They report `saved_hardware_unchanged` and `live_policy_reconcile_pending`; the saved hardware register can retain its earlier byte. Initial profiles without brightness intent read saved/live registers and retain their exact observations as baseline provenance. They do not claim to recover Synapse's retained enable/value. Initialization avoids rounding and rewriting an unchanged raw live byte.

Simulator checks cover exact packets, first-profile baselines, frame-before-brightness ordering, suppression/resume, active-profile changes, ownership/budget refusals, partial failures, reconnect, unchanged ticks and standalone-core refusal before lighting writes. The separate [physical one-frame probe](validation/ornata-one-frame.json) accepted seven writes in38ms with readable registers unchanged and the stock owner restarted afterward.

The [physical API probe](validation/host-static-api.json) additionally exercised the actual source-effect handler from a fresh native Store: initialized observed brightness provenance, saved Static RGB(16,32,48), accepted seven frame packets, reconciled the policy once and shut down the runtime. Mode3 with its undeclared parameter, profile0 CustomFrame8, saved effect3 and live/saved brightness255 remained unchanged at both checkpoints. The one-test process completed in0.76seconds. Fifteen stock user processes were observed after restart. A subsequent read-only discovery query with the restarted owner running failed; it was not retried. This does not establish optical output, previous RGB/animation-phase restoration, input recovery or the remaining Static activation/suppression/hotplug workflows.

Known process checks are not a global ownership lease. RGB buffer contents and previous animation phase cannot be read back through these checks. Other host effects remain unfinished; recovered [uniform animation math](UNIFORM-LIGHTING.md) alone is not a running animation engine.

Legacy single-zone and synchronized CLI color/effect actions now refuse exact Ornata interface2 firmware projection unless a fresh query reports Normal Mode0. Driver3, other modes and failed queries cause no effect writes or profile save. Disabled lighting ownership refuses before the query. These callers do not silently acquire the tray host runtime; low-level device transport remains available to explicitly scoped bridges and recovery tools.

`tools/Test-HostStatic.ps1` wraps the ignored physical test with explicit `-WriteOneFrame` and an exact compiled test executable. Build with `cargo test -p secbird-tray --no-run`, then supply the emitted test executable path. It requires an initially running stock owner, fresh report/config paths, bounded stock isolation, a60second child timeout and restart attempts in `finally`. The committed wrapper generalizes the executed workspace wrapper's paths and checks; that path adaptation was syntax checked rather than rerun solely to repeat a physical frame. Ordinary tests never select this probe.
