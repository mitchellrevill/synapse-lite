# Opted-in Ornata uniform runtime

This document records the initial runtime baseline. The later [control sampling checkpoint](UNIFORM-CONTROL-CHECKPOINTS.md) changes worker control-query frequency and adds timing diagnostics; explicit actions retain the strict path.

This checkpoint connects source Spectrum (UI3/native4) and fixed one/two-color Breathing (UI2/native5) to the bounded Ornata host-frame transport. It has simulator coverage and one bounded physical backend/worker test. Native3 is Reactive. Random Breathing and ambiguous black second-color/count behavior remain unsupported.

## Admission and persistence

Explicit source-effect selection creates an exact-program `uniformHostIntent` marker in the native source envelope, outside the decoded vendor document. Bare/default profiles and foreign imports receive no marker. Native backups retain it; Synapse4 export does not export that marker. Reconnect/startup may resume only an already opted-in profile. Importing an animation does not silently authorize streaming.

Normal_Mode0 keeps the established firmware code path. Driver_Mode3 requires exact PID025D/interface2/6x22, matching connected device and effective profile, enabled lighting ownership, a clear known-process check, candidate budget validation, fresh mode3, and existing profile0/region0 CustomFrame8/flags0/rate0/count0. There is no mode acquisition, profile1 effect SET or firmware fallback in Driver3. Known-process checks do not prove WDL, recorder, OTFM or arbitrary third-party ownership absent.

The action persists only after a complete seven-OUT frame and fresh mode/CustomFrame control checks, or saves an explicitly deferred choice under display/idle/global suppression. Initial raw brightness bootstrap is observational and retains provenance; it does not force LIVE brightness. Subsequent host effect changes and policy resume preserve its exact observed LIVE byte while that provenance still agrees with the typed enabled/value projection. Relative global-away dimming scales that raw byte before restoration. Explicit brightness edits clear the marker and use configured percentages; imported brightness intent uses that existing percentage path. ## Worker and local timing policy

One joinable thread services the existing shared Engine through `try_lock`; there is no per-frame spawn and the worker skips a busy UI/server lock. The tray starts it only in ordinary runtime, never `--runtime-smoke`, serve or native-smoke. No default profile streams. Store JSON is cached by path, modification stamp and length, with explicit invalidation after local actions; known-process/idle policy is sampled before each eligible batch. External edits that preserve both file length and modification timestamp can evade that cache signature.

The source-derived palettes remain exactly943/175/350 entries. Scheduling is our local policy: nominal40ms eligibility, at most one next table entry per tick, at least8ms between batches, no catch-up burst, freeze while blocked/suppressed, resume at the next unsubmitted entry. The shipped outer scheduler and its pause/drop/phase behavior are not recovered. This is not a certified25fps implementation or stock wall-clock/phase parity. Four fresh control GETs plus seven OUTs can make an achieved cycle substantially slower; no guards were removed to claim a frame rate.

Cached diagnostics expose accepted frame count, session wall elapsed (includes pauses), actual latest submission/gate microseconds, packet counts, current palette index, nominal interval and uncertified cadence. The bounded physical run below measures these counters; it does not certify sustained cadence or a complete cycle. Accepted OUT plus unchanged readable control state does not verify optical RGB, input behavior or exclusivity.

## Failures and shutdown

Each batch has cooperative cancellation/deadline checks and no automatic OUT retry. HID syscalls cannot be interrupted and postflight reads may extend the nominal budget. A possibly partial/error batch latches the device, including when a failed new choice leaves an older opted-in program on disk. Ticks must not repaint that old program automatically. Failed Static replacement with unknown packet counts reports those counts as unknown. Invalid choices rejected before output preserve an existing stream. Explicit new selection or reconnect can recover with a fresh playback generation.

Worker readiness uses shared alive/stop atomics, with RAII invalidation for normal exit, panic and poisoned Engine-lock exit. A stale `enabled` flag cannot advertise an active worker. Shutdown signals and joins outside the Engine lock for up to2s; on timeout/panic it reports that cleanup was not claimed and avoids acquiring that potentially busy Engine, including repeated Windows shutdown callbacks. A blocked syscall may outlive that interval. This restores no vendor animation phase and claims no global hardware lease.
