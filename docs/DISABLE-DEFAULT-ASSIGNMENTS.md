# Disable and restore-default local assignments

This change connects the existing source-derived Default/Disable Customize forms to a local desired-assignment store. Only source-enabled inputs and advertised categories can save. The primary mouse click and source-disabled keyboard/media inputs remain immutable. Standard and Hypershift records are separate and profile-specific.

Selecting Default or Disable creates a dirty draft; UNDO restores the opening snapshot, CANCEL discards it, and navigation asks to save/discard. Saving checks the current persisted profile against the opening snapshot and rejects stale owners. The existing worker performs atomic Store persistence. Imported `_synapseLiteSynapse4` data and unknown profile fields are preserved. Local choices are retained in `_synapseLiteLocalAssignments`, overlaid only for Customize display; this is deliberately not a hardware-delivery or global routing contract. A local Default overrides a source custom mapping without deleting it. The Customized drawer excludes explicit Default rows.

Evidence: existing docs/validation/customize-assignment-native.json retains source605 popup1270/source196 popup257 artifact hashes, REA IDs and geometry. No approved tab redesign or source geometry change is included. The additional UNDO control and local-delivery explanation are Lite adaptations, not established source parity.

Remaining acceptance: matched-geometry/DPI screenshot comparison of the enabled Save and Undo states; native HWND tests of local saves and pending navigation; actual Ornata mapping readback and mouse layer delivery/recovery. No physical input, device writes or clipboard test is introduced. Complete-build memory under100MB remains a separate unverified goal.
