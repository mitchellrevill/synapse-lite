# Uniform program checkpoint

Later production integration and bounded hardware results are documented in [the uniform runtime](UNIFORM-RUNTIME.md). Statements below describe this earlier checkpoint.

This checkpoint is not running animation playback. It adds pure program/scheduler logic and a separately callable bounded frame adapter. There is no worker, timer, endpoint integration or automatic default-profile playback yet. No physical HID or stock process was accessed by these tests.

The existing core `UniformCycle` supplies ordinary RGB table math recovered from the installed native engine. Evidence, native addresses and limitations are in `UNIFORM-LIGHTING.md` and `outputs/research/native-spectrum-breathing-math.md` in the task workspace. Derived fixtures are not vendor execution or optical observations.

|---|---:|---:|---:|
| Spectrum | 3 | 4 | 943 |
| Fixed one-color Breathing | 2 | 5 | 175 |
| Fixed two-color Breathing | 2 | 5 | 350 |

Native3 is Reactive. These numbers must not be interchanged with firmware effect IDs. Fixed Breathing uses the current native Zone projection; random colors and latent black second-color/count semantics remain unsupported. Per-key/off overrides do not become uniform programs.

`Program` binds a native-only opt-in marker to the exact Spectrum/fixed-color program. Default/imported profiles have no opt-in. Changing the projection invalidates the old marker. The marker is outside retained `decoded` vendor content; tests verify the entire foreign export stays byte-identical when adding it. Production opt-in/endpoint wiring is a later unit.

`Playback` emits one color ticket at a time. A complete successful7/7 submission permits the next entry. A partial/error result retains attempted/accepted counts and latches failure without automatic retry. Generation/sequence checks reject stale or duplicate completions. The bounded LUT is the only color history.

The nominal interval is40ms, but the outer native scheduler is unrecovered. Our explicit local policy freezes phase while suppressed/blocked, resumes the next unsubmitted color, never skips LUT entries and never queues a catch-up burst. A late or slow submission slows the animation. There is no phase synchronization, certified25fps throughput, source wall-clock cadence parity or previous-animation restoration claim. The planned off-UI worker must measure/report costs before claiming performance.

The separate `host_uniform::io::submit` adapter requires exact025D/interface2/physical6x22 scope and existing profile0/region0 CustomFrame8. It uses `PreparedOrnataFrame` for six71-byte row arguments and the exact6-byte commit. It changes no mode, brightness, saved profile1 effect, input or macro state. Ownership/profile/policy validation remains the caller's job; this adapter is not an ownership token.

The adapter freshly observes mode before the batch and checks mode/CustomFrame after accepted OUTs. Optional before/after parameters remain separate; absent values do not compare as known-equal. Status distinguishes accepted USB calls, attempted calls and control-register verification. It cannot read/verify the physical RGB matrix or visible result. Cancellation/deadline checks are cooperative, including between postflight queries; an in-flight HID syscall cannot be interrupted and can extend the nominal budget. No OUT is retried.

Ten focused tests pass: full943/175/350 RGB fixture equality, wrap/order, suppression/block resume, late/slow pumps, stale completions, failure latching, exact opt-in/export preservation, and spy transport success/refusal/partial/postflight cases.
