# Lighting-only probe admission

The explicit `--runtime-lighting-probe` path is an active lighting measurement. Its admission helper is GET-only; after admission the ordinary opted-in uniform worker submits frames. This flag is separate from the existing `--runtime-smoke` path, which excludes the uniform worker. Historical read-only smoke measurements used fresh no-action configurations; that older flag alone does not prohibit generic profile/policy apply from an existing configuration.

Admission requires an existing exact serial-bound Ornata025D/interface2 physical 6x22 device and one lighting-only profile whose Spectrum/fixed-Breathing projection already has matching native opt-in. The shared pure validator rejects extra configured scope, typed nonlighting settings and action metadata. Preflight never creates an opt-in, initializes a profile, migrates keys, saves, calls generic apply or issues SET. It samples host/process facts prospectively without turning the policy runtime on; unknown required display/idle state is a refusal. Fresh mode 3, profile 0 CustomFrame 8 and live/saved brightness are queried. LIVE must already match configured intent or validated raw-bootstrap provenance, so admission cannot normalize an observed raw brightness through a guessed percentage.

After admission, exact canonical parsed Store content is pinned until process exit. The probe reads and parses current native JSON afresh before every worker candidate pass and brightness reconciliation. The file reader consumes at most 2MiB plus one overflow-detection byte; oversized, malformed, missing or changed configuration latches refusal before device I/O. This bypasses the normal parsed Store metadata cache, so preserving mtime and file length cannot hide a content edit. Whitespace/BOM-only rewrites with identical parsed content are allowed. Returning a changed file to its original contents does not clear the latch or replace the pin.

Those fresh bounded reads, parses and comparisons are deliberate probe-only overhead included in its measured CPU, tick duration and RAM. Ordinary runtime retains its existing metadata cache policy and performs no extra probe file read when no pin exists. Probe measurement therefore must disclose this additional validation cost; it does not measure an identical ordinary-runtime execution path. The pin is a local configuration boundary, not an interprocess device ownership lease or filesystem lock.

Tests use synthetic private stores and spy transports only. They prove GET-only admission, refusal with zero SETs, unchanged disk/provenance, raw 128 and raw 186 baseline preservation, changed/invalid content latching, bounded oversized-file refusal, semantic whitespace acceptance, and no extra probe read in ordinary mode. The same-size edit regression forcibly seeds an old approved Store into the cache with the changed file's current metadata stamp/length: the probe must still reject before any subsequent HID operation. No physical validation was performed by these tests.
