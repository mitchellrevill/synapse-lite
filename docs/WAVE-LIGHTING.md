# Linear cardinal Wave reconstruction

`secbird_core::wave_lighting::WaveCycle` implements the source default Quick Wave's linear cardinal math. It retains a small RGB palette and one phase byte per region cell. It has no vendor runtime, clock, HID access, physical key mapping or frame history. Engine/worker/UI code is unchanged. The [uniform palette](UNIFORM-LIGHTING.md) remains the shared RGB interpolation boundary.

Construction requires a `WaveRegion::new(canvas_rows, canvas_cols, left, top, right, bottom)`. These are explicit native logical grid coordinates with **half-open** bounds `[left,right) × [top,bottom)`, inside the caller's row-major canvas. Geometry uses height=`bottom-top`, width=`right-left`. Rendering writes only that region and leaves other canvas cells untouched. The caller must establish an installed device's actual source region separately; this module does not infer inclusive/exclusive bounds from advertised matrix dimensions or claim that a6×22 fixture proves a physical Ornata layout. Both axes are bounded1..64, with at most4096 cells, and empty/inverted/outside regions fail before allocation.

`WaveCycle::source_quick(region, CardinalDirection)` supports Up/Down/Left/Right only. It represents source native effect2 (UI Quick Wave4), default speed25, width100, pause0, cycles-1 and25fps. In the source native conversion **either boolean value** of counterclockwise selects a rotational mode: false→1024, true→2048. This linear API corresponds to that field omitted and split disabled. Arbitrary speed/angle, split, clockwise/rotational modes, pause, finite/trigger playback and custom stops are not accepted options.

Source direction angles0/180/270/90 for up/down/left/right become `(angle+270)*2π/360`, evaluated in f64 then stored f32. The native linear path zeroes sine/cosine components with magnitude below about0.0001. For these cardinal angles the reduced pairs `(sin,cos)` are up(-1,0), down(1,0), left(0,-1), right(0,1). The implementation uses these constants; it does not substitute Rust trig for arbitrary native CRT behavior.

With projected cardinal dimension D, geometry evaluates the separate f32 operations `step = (((25*4)/100)*D)/25` and `period = trunc(D/step)`. Width100 and four palette stops give `activeN=max(period,4)`. Keep this floating-point order: a9-cell axis produces24 frames, while22 and6 produce25. Both use a40ms intended frame interval. Replacing the expression with algebraic25 changes the source's byte sequence for some dimensions.

The shared native palette builder692E0 supplies source stops0/33/67/100 red/green/blue/red, preserving repeated f32 additions, endpoint duplication and truncation. Channel convention is explicit: source JS red integer0xFF0000 passes through AddEffect's swapRGBToBGR and becomes native packed0x0000FF, whose low byte is red. Rust uses ordinary `Rgb(255,0,0)`, not raw source or native packed integers. The same boundary applies to green/blue and fixtures contain ordinary R,G,B byte triples.

For local row/column coordinates the native pixel path computes `phase = trunc_f32((col*cos/width + row*sin/height)*period)`, and infinite unsplit palette index `(phase-frame) mod activeN`. The native renderer's bounded positive unsigned modulo is equivalent to the Euclidean reduction used here. State starts at frame0; each successful `next_frame` advances modulo activeN. `reset` returns to0. `render_frame(index, output)` is a non-advancing query and wraps even very large indices. An incorrectly sized output fails before pixel writes or index advance. Output must have exactly canvas_rows×canvas_cols colors; outside-region cells remain caller-owned.
