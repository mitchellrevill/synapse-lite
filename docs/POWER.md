# DeathAdder V3 HyperSpeed power controls

The source Power page has two separate settings: idle sleep in whole minutes and the battery percentage at which low-power mode begins. The core implements the threshold register for the verified wired/wireless product IDs 196/197 (00C4/00C5). The native page now connects source-derived cards and sliders to the shared device actions. Full interaction and visual parity remain unverified.

The threshold is one byte: GET `07:81`, SET `07:01`. The source displays `floor(raw * 100 / 255)` and encodes a displayed value with `ceil(percent * 255 / 100)`. Its rendered range is 5–100%, in steps of five. The raw and displayed APIs are separate because conversion loses information: raw 78 displays as 30%, but encoding 30% gives raw 77. Backups and temporary changes must retain the raw byte. Setters verify exact raw readback.

This setting belongs to root device configuration in the recovered application, rather than a selected profile. Product 196 also sets `alwaysReadPowerSavingFromDevice`; its sleep workflow reads hardware instead of persisting the generic local `powerSavingValue`. The threshold must not be silently added to profile interchange. The source disables its control above an effective polling rate of 1000 Hz, using the applicable connection mode's polling value. The threshold register is separate from the command that reports whether the device is currently in low-power mode.

Four core tests cover all twenty displayed values on both scoped product IDs, exact restoration of all 256 raw bytes, invalid values rejected before transport, and unsupported models/registers. Two hardware-harness tests cover restoration encoding for stage slot IDs and the raw threshold. These simulator checks do not prove real wireless operation.

The physical wired mouse passed eight setting checks, including a threshold change to 25% (raw 64), followed by byte-for-byte restoration of every captured register. The harness snapshots and saves the original raw threshold before any mutation; failure to capture it prevents the roundtrip. Stock user processes were temporarily closed, then restored, with ten processes observed after three seconds. Services, drivers, input mappings, macros and profile files were unchanged. See [the scoped hardware result](validation/power-hardware.json).

This verifies command/readback/restoration on the installed wired mouse. Actual battery-triggered mode transitions, battery drain, sleep/wake, wireless behavior, editor event routing and the complete Power workflow remain unverified.

## Native page and shared actions

The full recovered stylesheet, private source fonts and inert recreated markup were measured at CSS widths 1280, 1266 and 1000, with low-power mode enabled and disabled. At 1280 and product-local navigation bottom 86, the cards are (30,106,600,193) and (650,106,600,193); below 1280 the second card wraps to y319. Its high-polling warning adds 32 px to card height. The sliders are 520 by 64, offset (40,99) inside each card. The host's 42 px strip is supplied separately. Three native geometry tests cover measured wrapping, warning/scroll offsets and unsupported viewports.

Pointer capture keeps slider changes local until release. The request retains the physical device key; switching devices or losing capture cancels the unfinished gesture. Resizing also cancels it because cached pointer geometry is no longer valid. The numeric bubble uses the source formula and private Roboto font, with native text measurement. Browser/native pointer transfer, fractional rasterization, hover/active thumb styling, source help tooltips, keyboard and accessibility behavior still need end-to-end verification. Read errors disable the affected control and expose the error instead of inventing a default value.

`/api/critical-threshold` requires matching full `id` and `expected_device`, a supported percentage and an actual hardware polling rate at most 1000 Hz. The action validates the entire prospective native backup budget before writing hardware, then verifies the exact raw threshold and saves `DeviceProfiles.power` independently of every profile. `/api/device-sleep` uses the same physical identity boundary and verifies exact raw seconds, without adding a profile-local sleep value. Existing legacy `/api/sleep` and native profile sleep behavior remain available.

New Synapse imports/default profiles for 196/197 preserve `powerSavingValue` in opaque source data and mark `deviceSleepScope:true`; they do not turn that template field into a profile activation command. Tests verify that a live four-minute timer survives source profile activation. An explicit typed sleep override still exports, and removing that override restores the retained opaque source field. Native JSON and historical profiles without the new provenance marker retain their previous override/deletion behavior. Automatic migration of those historical profiles remains unresolved; no private store is rewritten.

Native backups preserve device-wide Power data and unknown fields. Conflicting incoming intent is retained in compatibility metadata. Synapse profile export warns when device-wide Power settings cannot be represented by its profile-only format. A successful hardware write followed by a filesystem save failure is still reported as a failure; this does not promise transactional rollback across hardware and disk.

Three read-only runs of the native Power page presented both hardware-backed controls at 125% DPI, with two real devices and all three private fonts loaded. Working set peaked at 23,134,208 bytes, sampled private memory at 8,486,912 bytes; one replacement process and no process-owned TCP connections were observed. Stock Synapse was restored, with twelve user processes observed after three seconds. The exact tested executable and scope are in [Power page memory evidence](validation/power-native-memory.json); later compatibility edits do not retroactively change that checkpoint's hash. These runs do not prove pointer routing, help/keyboard behavior or battery transitions.
