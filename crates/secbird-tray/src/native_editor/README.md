# Native editor implementation boundary

This module draws with Win32 GDI and calls the existing device dispatcher directly on one worker. It starts no browser and opens no network listener. It uses layout facts recovered from installed AppEngine4.0.827 and locally cached Synapse product605/196 source. The source includes no copied vendor JavaScript or CSS.

Implemented native controls cover device selection, profile add/duplicate/rename/switch, bounded local profile import/export, DPI axes, polling rate, one lighting zone's brightness/static color/spectrum/breathing, sleep timeout, firmware-supported button assignment reads/writes and restore-all. Calibration/Advanced tabs are shown as unavailable. Complete keyboard drawer/state styling, all effects, per-key painting, macro editing, the original Synapse import/export modal, full source DOM/state parity, accessibility and exact Chromium text rendering remain incomplete. This is a partial source-based port, not verified pixel-for-pixel parity.

`open(Arc<Mutex<Engine>>)` runs a single editor on a dedicated UI thread. `run_standalone(engine, Some(duration))` exits the window after a smoke interval. The source-view smoke setting is accepted only for standalone timeout mode or `--runtime-smoke`: `SYNAPSE_LITE_SMOKE_VIEW=dashboard`, `mouse-performance`, or `keyboard-lighting`, `keyboard-customize`, `mouse-performance-polling`, `mouse-performance-independent`, or `mouse-performance-hidden`. It selects an actually detected matching device after the read-only snapshot and sends no mutation requests.

Runtime assets are loaded from `SYNAPSE_LITE_ASSETS` or an `assets` directory next to the executable. Fonts are loaded with `FR_PRIVATE` and removed on teardown. `provision_assets.py --evidence <local-recovered-evidence> --output <ignored-assets-directory>` copies the three reconstructed source fonts and converts the original mouse/keyboard model AVIF artwork to BMP against the source background color. It records hashes in provenance.json. Pillow is an authoring dependency only. Generated vendor assets must remain excluded from public source commits.

`source_layout.rs` loads the locally recovered Customize geometry rather than embedding vendor paths in the executable. `SourceLayout::load` validates the JSON; `hit_test` and `bounds` use the same SVG meet transform as `trace_key_path`, which leaves source curves in a GDI path for the caller's active/hover styling. The recovered current Ornata edition0/layout6 has109 paths and three additional dial actions without independent geometry. Unknown path commands are rejected. The source snapshot and historical device observation must agree before the provisioner adds `keyboard-layout.json` and the exact `keyboard-customize.bmp`; neither host locale nor a generic keyboard image selects layout. `--icons-from` optionally copies previously rasterized source icon assets and their provenance from a local ignored directory. No asset download is performed.

The source recovery specification and machine-readable CSS rules/font metrics are separate research deliverables. Native smoke memory results establish only the measured workload and duration; they do not establish complete functional or visual acceptance.

Profile Add creates recovered model defaults and activates the new profile; Duplicate renews its foreign GUID and activates the copy. Rename uses an inline 32-character input. Import/export use native Windows file dialogs, with a choice of Synapse 4 or Secretarybird-compatible output. Original Synapse modal parity is unfinished. Unsupported translated fields are retained and reported in a scrollable Help control. The dropdown follows the recovered 230px width and 25px rows; its seven-row viewport supports the mouse wheel. Full hover, keyboard dropdown navigation, linked-game management, reset and delete interactions remain unfinished. Form drafts survive a resize or worker refresh within the same device/profile/tab.

The Ornata Customize view now draws the locally recovered UK edition0/layout6 artwork at730x340 with its source730x387 overlay at the same origin. Two10px body paddings plus the6px block margin place it26px below the navigation bottom. Known firmware IDs select the existing shared assignment editor; unmapped source inputs explicitly report the gap. This is conditional on the provisioned local layout evidence and product025D. Global stock host clipping, active/hover styling and source drawer behavior remain unverified.

Product 196/197 Performance now uses performance_layout.rs and performance_view.rs: source nonlinear range anchors, stage rows, hidden/independent intent, hover controls and polling buttons. Native input windows use the source Arial 14 font and clip around spinner/body regions. Edits route through the shared typed intent endpoint with an expected-profile guard. Slider edits commit on release, numeric edits on blur, and spinner repeat follows 300 ms. A bounded ordered queue coalesces adjacent setting updates and drains accepted work when closing. Full native pointer/focus/keyboard routing and layer/raster equivalence remain to be verified.

The independent/hidden smoke variants are explicitly presentation-only overrides of the local render model. They do not change device settings or stand in for functional input tests. PerMonitorV2 awareness is declared in app.manifest; the measured display reported scale 1.25 and per-monitor awareness.
